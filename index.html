編集工程

メモを、材料に。材料を、文章に。文章を、A4へ。

  1. memo 雑に貼る

    箇条書き、技術名、思い出せる作業だけで始める。

  2. extract 拾う

    役割、規模、成果、工夫に線を引く。

  3. question 聞く

    足りない材料だけ、答えやすい質問に変える。

  4. compose 組む

    A4一枚の職務経歴書として読める密度にする。

無料プレビュー

使用技術と担当作業は書けていますが、採用担当者が知りたい「役割」「規模感」「成果」が不足しています。 このままだと指示された作業をこなした印象になりやすいため、既存コードを読み解いた経験や不具合調査の流れを補うと強くなります。

使える材料

  • Java / Spring Bootで業務システム改修を経験
  • 画面、バックエンド、SQLにまたがる改修の可能性
  • Reactで管理画面の修正経験
  • 詳細設計書を見ながら実装した経験

補いたい材料

  • 「バグ修正」だけでは調査力が伝わらない
  • 「SQLも少し」は弱く見えやすい
  • テストの担当範囲が曖昧
  • 数字や利用者像がない
